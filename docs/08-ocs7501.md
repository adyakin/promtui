# Milestone 8 — Terminal Program Status (OSC 7501)

## Objective

Implement OSC 7501 terminal program status reporting for PromTUI.

The feature should work in terminals supporting OSC 7501, including Rex and compatible iTerm2 versions, without requiring terminal-specific executables, APIs or integrations.

It must also work when PromTUI runs remotely over SSH, provided the terminal path supports forwarding the escape sequences.

Do not implement Rex-specific features in this milestone.

## 1. Protocol

Implement OSC 7501 using the documented protocol.

Before implementation, verify the exact escape sequence syntax, supported states, message fields and reset semantics against the official protocol documentation.

Do not invent protocol fields or unsupported states.

Use the appropriate OSC terminator.

Keep protocol encoding isolated in a small, testable component.

## 2. Query Lifecycle

Integrate status reporting with the existing PromQL execution lifecycle.

### Query started

Emit:

- State: `working`
- Message: `Executing PromQL query`

Emit immediately when a query begins.

### Query succeeded

Emit:

- State: `done`
- Message: `Query completed`

A successful query returning zero results is still successful.

### Query failed

Emit:

- State: `error`
- Message: `Query failed`

Do not include the complete query, credentials or potentially sensitive backend details in terminal status messages.

The existing UI should continue to display detailed errors.

### Query cancelled

Return to an appropriate non-working state.

Do not report user-initiated cancellation as a query failure.

### Application exit

Clear or reset the program status using the protocol's documented behavior.

## 3. Concurrent and Stale Operations

Ensure that status transitions correspond to the currently relevant query.

Requirements:

- Assign an execution identity or generation to each query.
- A stale query result must not overwrite the status of a newer query.
- Handle cancellation correctly.
- Handle rapid consecutive query executions.
- Do not leave the terminal permanently in `working` after failures or cancellation.

Avoid introducing a new query scheduler solely for this feature.

Reuse existing execution lifecycle mechanisms.

## 4. Background Operations

Do not report routine background activity in this milestone.

Specifically exclude:

- Automatic Alerts refreshes
- Automatic Targets refreshes
- Saved Queries file operations
- Autocomplete requests
- Routine UI updates

Only explicit PromQL query execution should affect OSC 7501 status.

This prevents periodic activity from continuously changing the terminal status.

## 5. Terminal Compatibility

The feature must not depend on:

- Rex CLI
- Rex Lua
- Local terminal processes
- Terminal-specific environment variables
- Terminal pane APIs

The application should remain functional in terminals that do not support OSC 7501.

Unsupported terminals should simply ignore the sequences without affecting normal application behavior.

Do not assume that `TERM` alone reliably identifies OSC 7501 support.

Consider a small configuration option to disable status emission if needed, but avoid unnecessary terminal detection complexity.

## 6. Output Integration

Integrate OSC emission safely with the existing Bubble Tea rendering architecture.

Requirements:

- Do not write escape sequences concurrently with Bubble Tea rendering from arbitrary goroutines.
- Do not corrupt terminal output.
- Do not interfere with Kitty graphics rendering.
- Do not introduce flickering.
- Ensure output ordering is deterministic.
- Preserve existing query execution and UI behavior.

Prefer a single coordinated terminal-output path.

## 7. Configuration

Keep configuration minimal.

If a setting is introduced, use:

```yaml
terminal:
  program_status: true
```

Default to enabled unless testing reveals a compatibility issue requiring a different default.

Do not introduce Rex-specific configuration.

## 8. Testing

### Protocol tests

Verify:

- Correct OSC sequence encoding
- Correct terminators
- Valid status values
- Message encoding and escaping
- Reset behavior

### Lifecycle tests

Verify:

- Start → Working
- Success → Done
- Failure → Error
- Cancellation → Idle
- Rapid consecutive queries
- Stale completion handling
- Application exit cleanup

### Integration tests

Verify that OSC emission does not corrupt:

- Bubble Tea UI
- Kitty graphics
- Editor input
- Existing query results

### Manual verification

Test in:

- Rex terminal
- iTerm2
- SSH session from a supported terminal
- A terminal without OSC 7501 support, if available

Document any terminal-specific limitations observed.

Do not claim remote SSH compatibility has been verified unless it has actually been tested.

## 9. Documentation

Create `docs/MILESTONE-8.md`.

Document:

- Protocol implementation
- Query lifecycle mapping
- Configuration
- Output integration
- Tests performed
- Manual verification results
- Known compatibility limitations

Review all applicable `docs/uix*.md` files before implementation.

Do not automatically proceed to Rex-specific integration.

## 10. Acceptance Criteria

Milestone 8 is complete when:

- Query execution emits `working`.
- Successful queries emit `done`.
- Failed queries emit `error`.
- Cancellation clears working status.
- Stale executions cannot overwrite newer statuses.
- Application exit resets status correctly.
- OSC output does not corrupt the TUI or Kitty graphics.
- No Rex-specific dependencies are introduced.
- Existing functionality remains unchanged.
- Tests and documentation are complete.
